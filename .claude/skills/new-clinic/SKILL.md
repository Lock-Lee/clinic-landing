# เปิดคลินิกใหม่

อ่าน `docs/business.md` (แพ็กเกจ สิทธิ์) และส่วน "หลังบ้าน" ใน `docs/architecture.md` ก่อน

## 1. เก็บข้อมูลให้ครบ (ถามผู้ใช้ถ้าขาด อย่าเดา)

| ข้อมูล | ตัวอย่าง | หมายเหตุ |
| --- | --- | --- |
| รหัสคลินิก (`--id`) | `lumiere` | a-z 0-9 - ใช้เป็น `CLINIC_ID` และโฟลเดอร์รูป เปลี่ยนทีหลังยาก |
| ชื่อคลินิก | Lumière Clinic | |
| แพ็กเกจ | Starter / Standard / Premium | Starter ต้องซื้อส่วนเสริมหลังบ้าน (+3,900) ถึงจะมีบัญชี |
| แม่แบบ (`--template`) | `starter` / `standard` / `premium` | ปกติตรงกับแพ็ก ใช้แม่แบบสูงกว่าแพ็กได้ แท็บที่เกินจะถูกล็อก |
| ลิงก์เว็บ + โดเมน | https://lumiere.co.th | โดเมนจดในชื่อคลินิก |
| อีเมล + ชื่อแอดมินคลินิก | | หนึ่งคนต่อหนึ่งอีเมล |

ข้อมูลคลินิกจริงของลูกค้าใช้ได้ (ลูกค้าให้มาเอง) แต่ห้ามเอาไปใส่ใน `seed-data.ts` หรือเทสต์

## 2. สร้างคลินิกและบัญชี

ต้องเปิด Docker แล้ว (`bun run db:up`) แล้วรัน:

```bash
bun run clinic:new --id <id> --name "<ชื่อ>" --package <แพ็ก> --template <แม่แบบ> --site-url <url> --domain <โดเมน> --email <อีเมล> --user-name "<ชื่อ>"
```

- รหัสผ่านชั่วคราวถูกเขียนไว้ที่ `.onboarding/<id>.txt` (ไม่อยู่ใน git)
- **ห้ามอ่านไฟล์นี้หรือพิมพ์รหัสลงแชท** บอกผู้ใช้ให้เปิดไฟล์เอง ส่งให้คลินิกทาง LINE หรืออีเมล แล้วลบไฟล์ทิ้ง
- คลินิกเข้าครั้งแรก ระบบจะบังคับให้ตั้งรหัสใหม่
- บัญชีเพิ่มเติมหรือรีเซ็ตรหัส ให้ทีมงานทำในหน้า "ผู้ใช้" ของ admin กลาง

## 3. เนื้อหาตั้งต้น

- เนื้อหาเริ่มจาก `editableDefaults` ของแม่แบบ (ข้อมูลสมมติของเดโม) ต้องแทนด้วยข้อมูลจริงของคลินิกก่อนเปิดเว็บ
- ถ้าลูกค้าส่งข้อมูลมา: ใส่ผ่านหลังบ้านของคลินิกนั้นใน admin กลาง (ทีมงานเห็นทุกคลินิก) หรือเขียน JSON แล้ว PUT ผ่าน `saveContent(<id>, data)` ใน `@repo/db`
- เนื้อหาการแพทย์: เป็นข้อมูลทั่วไป ไม่อ้างผลเกินจริง ไม่มีภาพก่อน-หลัง ใส่ "ผลลัพธ์ขึ้นอยู่กับแต่ละบุคคล" ตามเกณฑ์ สบส.

## 4. เว็บคลินิก

- deploy แอปของแม่แบบนั้น (`apps/clinic-starter-demo`, `apps/clinic-demo`, `apps/clinic-full-demo`) แยกหนึ่งโปรเจกต์ต่อหนึ่งคลินิก
- ตั้ง env: `CLINIC_ID=<id>`, `DATABASE_URL`, `S3_*` (ดู `.env.example`)
- เว็บจริงต้องเอาแถบเดโม (`demo-bar`) และ `robots: noindex` ออก และเปลี่ยน `url` ของคลินิกเป็นโดเมนจริง
- ถ้ายังไม่ได้ deploy จริง บอกผู้ใช้ตรงๆ ว่าขั้นนี้ยังค้าง

## 5. ตรวจ

1. login admin กลางด้วยบัญชีทีมงาน → เห็นคลินิกใหม่ แพ็กถูก แท็บที่ล็อกตรงกับแพ็ก
2. เปิดเว็บด้วย `CLINIC_ID=<id>` แล้วเห็นเนื้อหาของคลินิกนี้
3. สรุปให้ผู้ใช้: สร้างอะไรแล้ว, ไฟล์รหัสอยู่ไหน, ขั้นไหนยังค้าง (deploy, โดเมน, เนื้อหาจริง)
