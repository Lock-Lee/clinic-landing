# ตรวจก่อนส่งงาน

รันตามลำดับ รายงานผลทุกข้อ (ผ่าน / ไม่ผ่าน พร้อมหลักฐาน) ห้ามบอกว่าผ่านถ้าไม่ได้รันจริง

## 1. โค้ด

1. `bun run typecheck` ผ่านทุก workspace
2. Docker เปิดอยู่ (`docker ps` เห็น `clinic-db`, `clinic-s3`) แล้ว `bun run test:e2e` ผ่านทั้งหมด
3. ถ้าจะ build: ต้องปิด dev server ทุกตัวก่อน (กติกา repo) แล้ว `bun run build`
4. `git status`: ไม่มีไฟล์ที่ไม่ควร commit (`.env`, `.onboarding/`, `test-results/`, รูปทดสอบ, ไฟล์ใหญ่ที่ root)

## 2. ข้อมูลลับ

- ไม่มีรหัสผ่านจริง, API key, token ในโค้ด (รหัสใน `packages/db/seed-data.ts` เป็นของเดโมเท่านั้น และต้องไม่ใช้กับเครื่องจริง)
- production ต้องตั้ง `DATABASE_URL`, `S3_*` ใหม่ ห้ามใช้ค่าใน `.env.example` / `docker/s3.json`
- ค้นหาคำต้องสงสัย: `git diff --cached | grep -iE "password|secret|token|api[_-]?key"` แล้วดูทีละจุด

## 3. ธุรกิจ

- ราคาใน `apps/landing/app/content.ts` (การ์ด + FAQ) ตรงกับ `docs/business.md`
- สิทธิ์แต่ละแพ็กใน `packages/db/src/plans.ts` ตรงกับที่เขียนใน `docs/business.md` และการ์ดราคา
- ลิงก์ `demoUrl` ในการ์ดราคา: ถ้าจะขึ้นเว็บจริง ต้องไม่ใช่ `localhost`

## 4. เนื้อหาและกฎหมาย

- เดโม: ข้อมูลสมมติทั้งหมด มีแถบเดโม `robots: noindex`
- เว็บคลินิกจริง: ไม่มีแถบเดโม ไม่มี noindex `url` เป็นโดเมนจริง
- เนื้อหาการแพทย์: ไม่อ้างผลเกินจริง ไม่มีภาพก่อน-หลัง มี "ผลลัพธ์ขึ้นอยู่กับแต่ละบุคคล" (เกณฑ์ สบส.)
- ฟอร์มที่เก็บชื่อ/เบอร์มีช่องยินยอม PDPA

## 5. มือถือ

- ทุกหน้าที่แก้ใช้ได้ที่ 375px ไม่เลื่อนแนวนอน (`e2e/tests/mobile.spec.ts` ครอบคลุมหน้าหลัก หน้าใหม่ต้องเพิ่มในไฟล์นี้)

## 6. รายงาน

สรุปเป็นตาราง ข้อ / ผล / หลักฐาน (คำสั่งที่รัน, บรรทัดผลลัพธ์) และบอกสิ่งที่ยังค้างหรือไม่ได้ตรวจตรงๆ
