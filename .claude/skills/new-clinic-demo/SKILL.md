# สร้างเว็บเดโมใหม่

อ่าน `docs/architecture.md` และ `docs/business.md` ก่อนเริ่ม

## 1. เลือกแม่แบบ

| ลูกค้าต้องการ | แพ็กเกจ | คัดลอกจาก |
| --- | --- | --- |
| หน้าเดียวยิงโฆษณา | Starter / Standard | `apps/clinic-demo` |
| เว็บคลินิกหลายหน้า บริการแยก บทความ | Premium | `apps/clinic-full-demo` |
| คลินิกหลายสาขา โปร สมาชิก | Premium | `apps/clinic-branch-demo` |
| เว็บบริษัท/เอเจนซี | - | `apps/agency-demo` |

ถ้าลูกค้าส่งลิงก์อ้างอิงมา ให้เปิดดูด้วย browser ก่อน จดว่ามีหน้าอะไร section อะไร แล้วเลือกแม่แบบที่ใกล้ที่สุด

## 2. คัดลอกและตั้งค่า

1. `cp -R apps/<แม่แบบ> apps/<ชื่อใหม่>` แล้วลบ `.next` ในโฟลเดอร์ใหม่ถ้ามี
2. `package.json`: เปลี่ยน `name` และพอร์ตใน `dev`/`start` เป็นพอร์ตถัดไปที่ว่าง (ดูตารางใน `docs/architecture.md`)
3. เพิ่ม script `dev:<ชื่อ>` ใน `package.json` ที่ root
4. `bun install`

## 3. เนื้อหาและหน้าตา

- แก้ `app/content.ts` ที่เดียว: ชื่อ บริการ ราคา รีวิว FAQ สาขา
- สี: token ใน `:root` ของ `app/globals.css`, ฟอนต์: `app/layout.tsx` (ต้องมี subset `thai`)
- **ข้อมูลต้องเป็นของสมมติ** ห้ามใช้ชื่อ โลโก้ ข้อความ รูป หรือชื่อแพทย์ของคลินิกจริง เว้นแต่คลินิกนั้นเป็นลูกค้าที่ให้ข้อมูลมาเอง
- คงไว้: `DemoBar`, `robots: noindex`, หมายเหตุ "ผลลัพธ์ขึ้นอยู่กับแต่ละบุคคล", ช่องยินยอม PDPA ในฟอร์ม
- เนื้อหาการแพทย์เขียนเป็นข้อมูลทั่วไป ไม่อ้างผลเกินจริง ไม่มีภาพก่อน-หลัง

## 4. ตรวจ (ห้ามข้าม)

1. `bun run typecheck` จาก root ต้องผ่านทุก workspace
2. รัน dev เฉพาะแอปนั้น (`bunx turbo run dev --filter=<ชื่อ>`) **ห้าม build ระหว่าง dev เปิดอยู่**
3. `curl` ทุก route ต้องได้ 200 และ slug ที่ไม่มีต้องได้ 404
4. หน้าจอมือถือ 375px: ทุกหน้า `document.documentElement.scrollWidth` ต้องเท่ากับ 375 และเมนูมือถือเปิด/ปิดได้
5. ดู console ไม่มี error (error จาก hot reload ระหว่างแก้ไฟล์ ให้รีโหลดหน้าแล้วเช็กใหม่)

## 5. ปิดงาน

- อัปเดตตารางแอปใน `docs/architecture.md` และ `README.md`
- ถ้าจะโชว์ในเว็บขาย เพิ่มรายการใน `showcase` ของ `apps/landing/app/content.ts`
